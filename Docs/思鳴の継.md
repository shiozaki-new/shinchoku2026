# 大阪展示会 思鳴の継

この文書はオーナーとAIの現在の合意である。履歴を追記せず、確定が変わったときは書き換える。
経緯と再発防止は [`継の記録.md`](継の記録.md) へ置く。

## 1 目的

大阪展示会について、認・思・鳴を判定可能な文へ確定し、会話履歴が無い次のAIでも同じ現在地から再開できる状態を作る。

HTMLページは合意を表示する応であり、ページを作ること自体は展示会の目的ではない。

## 2 幅

- 対象リポジトリは `imGonnaBeDevKing/shinchoku2026`
- 表示面はGitHub Pagesで配信可能な静的HTML
- 正本、会議項目、GitHub Issues、コミットは公開される前提で記載する
- 鍵、個人情報、未公開の契約情報、会場の保安情報は記載しない
- 大阪展示会の名称、開催日、会場、来場者、展示内容、予算、成功条件は未確定
- 未確定値は推測で補完せず、`認` または `思` に置く
- 展示会固有の実装は、成立条件の鳴が成立するまで開始しない

前提が破れた場合：公開できない情報が必要になった項目は、公開正本へ値を書かず、存在と判定方法だけを残す。公開そのものが不可能な場合は同一構造での実装を中止する。

## 3 許

全条件必須。定め手はオーナー。機械で判定可能な項目は `Scripts/handover_guard.py` が判定する。

1. セッション開始時に、正本・Git状態・Issue・会議項目の現在地を取得できる
2. 現在の合意と経緯が別ファイルであり、合意文書が日記化していない
3. 全会議項目に `stage`、`status`、`why`、`criterion`、`limit`、`owner`、`next_action`、`updated_at` がある
4. 未確定項目が `鳴`、`示`、`応`、`継` に置かれていない
5. 成立判定と上限が無い項目は実装へ降りない
6. HTMLの会議机は `Docs/会議項目.json` を読み、同じ値を表示する
7. GitHub Issueは「なぜ作るのか」「示」「応」「判定」を分離する
8. 規則を変更したコミットは、自動検査が通らなければ成立しない

## 4 現在の合意

### 確定

- 名称：大阪展示会 思鳴会議室
- 応：HTMLのWebページをこのリポジトリへ構築する
- タトてで成立したAI引き継ぎの構造を移植する
- 移植対象は、正本、開始時の現在地取得、鳴分岐、機械的成立条件、停止、GitHub Issue、差分記録
- タトて固有の製品仕様、Apple配信処理、秘密情報は移植しない

### 未確定

- 大阪展示会は誰を対象とするか
- 来場者に何を実体化するか
- 何をもって展示会の成功と判定するか
- 開催日、会場、予算、展示内容、計測値

次にオーナーへ聞く一問：**大阪展示会で、誰に何が起きたら成功ですか？**

## 5 引き継ぎ

次のAIは、最初に `sh Scripts/session_start.sh` を実行する。
会議項目の成立判定と上限を読み、未確定の最上位項目を一つだけ質問する。
展示会固有の値を既存HTMLや旧進捗ダッシュボードから推測しない。
