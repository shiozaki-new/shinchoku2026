# 継の記録

日付順の日記ではなく、同じ不成立を繰り返さないための主題別記録とする。

## 会話履歴は正本にならない

会話は次のAIへ自動で渡るとは限らない。確定した値をチャットだけへ残すと、次周回で再質問か推測が発生する。

対策：現在の合意は `思鳴の継.md`、会議項目は `会議項目.json`、作業はIssueとコミットへ帰属させる。

## 手で書いた現在地は古くなる

ブランチ、未コミット、リモートとの差、Open Issueは作業中に変わる。文書へ転記すると、文書更新が止まった時点で誤った現在地になる。

対策：`Scripts/session_start.sh` がGitとGitHubから毎回取得する。

## 文章だけの規則は通過できる

「必ず読む」「必ず判定を書く」という文だけでは、読み飛ばして実装できる。

対策：`Scripts/handover_guard.py`、pre-commit、GitHub Actionsで必須項目と層の矛盾を検査する。

## 未確定の補完は手戻りを作る

展示会の対象や成功条件を既存画面から推測すると、表示は作れても合否が決まらない。

対策：未確定項目を `認` または `思` に残し、定め手と次の一問を明記する。

## 移植対象と固有実装を分ける

タトての引き継ぎ構造は再利用できるが、Apple配信、アプリ固有の許、秘密情報は大阪展示会の幅に入らない。

対策：移植するのは正本、現在地取得、鳴分岐、機械判定、停止、Issue、差分記録に限定する。
